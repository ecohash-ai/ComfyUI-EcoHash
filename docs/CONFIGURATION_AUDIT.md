# 连接、模型发现与节点配置审查

本次检查基于本地 ComfyUI 插件与 `code/ecohash/ecolink` 源码（2026-10-19）。
本地平台代码与已部署 API 可能存在版本差异；源码支持不等于线上实例已经通过验证。

## 已调整的配置流程

专有节点：选择连接 → 选择模型 → 填写任务参数 → 连接输出 → 运行。
设置顶部配置一次全局 EcoHash API Key，公共模型与 EcoHash 专有实例共用。
从节点进入连接设置，保存后立即绑定该连接并查询模型列表。新增官方连接只需要显示名称和 API 地址；
自动生成连接 ID，超时和第三方端点独立密钥放在高级设置。可粘贴完整生成地址，服务端会保存对应 API 前缀。

- 节点顶部显示连接名称与 ID，未配置的默认 `dedicated` 不再作为有效连接推荐。
- 只有一个有效连接或本次明确选择过的连接，才作为新节点默认连接；已有工作流不自动改绑。
- 已发现的单个模型可填入空模型字段；多个模型需要选择。手动 ID 保留为后备方式。
- 切换连接清空上一连接的模型；刷新列表保留已有模型 ID，避免悄悄替换模型。
- 隐藏内部连接字段和重复模型/音色字段；界面辅助控件不写入工作流或 API 请求。
- 节点不再显示连接状态字段，连接检测结果保留在连接设置中；节点显示运行状态和视频任务进度。
  模型信息行也已移除，能力说明放在选择器悬浮提示和连接设置中。模型发现错误显示在运行状态中。
  列表查询成功只验证该查询，不声称所有推理能力通过。
- 配置缺失在执行验证阶段报告具体连接名；私有接口校验错误显示脱敏原因。
- 无协议选择项，连接配置中也没有协议字段。
- 官方连接仅在准确的 `https://api.ecohash.com` 默认 HTTPS 端口上读取全局密钥，不复制到各连接中。
  修改全局密钥后，所有官方连接及公共/专有节点的相关缓存失效；第三方连接仍使用独立密钥。
  本次直接采用新配置方式，不提供旧版每连接密钥的迁移或保留覆盖规则。

## 各类节点的使用与限制

| 节点 | 主要配置 | 审查结果与边界 |
|---|---|---|
| 图像生成 | 模型、提示词、尺寸；可选步数/种子 | 自定义时才显示宽高；步数 0 留给服务。尺寸预设不保证每个模型支持。 |
| 图像编辑 | 输入图片、模型、编辑提示词、尺寸 | 默认 auto 使用输入图尺寸；按服务声明的编辑能力过滤，不按模型名称猜测。仅单图编辑。 |
| 语言模型 | 模型、模式、文本、生成长度等 | 自定义模式才显示系统提示词；文本输出可接图像/视频提示词。服务的采样参数能力不完整，不能声称每项适用于所有部署。 |
| 视觉描述 | 输入图片、模型、问题、生成长度 | 按输入模态过滤；声明支持图像输入的 llm 也可选，不按模型名称判断视觉能力。 |
| 语音合成 | 模型、文本、音色、语速 | 已提供音色元数据时显示选择器，否则手填；不再按某个模型名猜默认音色。当前要求 WAV 返回。 |
| 语音识别 | 输入音频、模型、可选语言 | 语言留空自动识别；当前使用同步转写接口。 |
| 视频生成 | 模型、提示词、时长、比例、分辨率 | 专有节点额外支持自定义宽高；无协议、步数、种子、帧率。音轨保留返回结果。恢复任务与等待超时在高级设置中。当前仅文生视频。 |

公共与专有分组表示调用入口，节点类型表示处理的数据，不表示某个品牌固定属于某类。
未来增加需要参考图、音频或视频的模型，仍需相应的参考输入节点能力；不能把“模型在列表里”
当作当前文生视频节点已支持所有生成模式。

## EcoLink 源码对应关系

| 来源 | 已有能力 | 插件处理 |
|---|---|---|
| `src/api/internal/handlers/platform.go`，`/platform/models` | category、输入/输出模态、video_max_duration_seconds | 按声明过滤，显示时长限制。未知能力保留未知。 |
| 同文件，`/platform/video-pricing` | 按模型、分辨率、是否视频输入区分的计费档位 | 公共文生视频读取无参考视频的档位，不维护按模型名称的分辨率表。 |
| `src/api/internal/inference/handler.go: ListModels` | `/v1/models` 默认只列聊天模型，`category=all` 列完整目录 | 专有发现请求加 `category=all`，避免图像、视频、语音漏列。 |
| `src/shared/models/platform.go` | 视频步数、FPS、CFG、长度换算方式由管理员维护 | 视频节点移除这些配置，不复制服务端模型规则。 |
| `src/api/internal/inference/video_openai.go` | `/v1/videos` 标准外观转换为已有任务 API | 专有节点默认标准请求；非标准部署可由管理员安装明确的请求映射。公共节点保留平台原有音轨/分辨率接口。用户无需选择传输格式。 |

模型列表刷新不依赖新发插件版本。离线时可使用快照/缓存，但会标明来源；这不保证模型仍可用。
公共快照不是运行时模型适配表。模型 ID（含路径、别名、实例后缀）原样发送，连接地址不按名称改写。

## 平台侧仍需解决的缺口

1. `ListModels` 为用户实例返回的条目当前缺少 category、输入/输出模态和兼容标志，
   而 `src/shared/models/inference.go` 已有 category、openai_compatible。
   应把真实实例元数据投影到实例条目；不应让插件通过模型名、路径或品牌补分类。
2. `CreateVideoJob` 直接按公共 `platform_models.model_id` 查询，尚未像图像、聊天入口那样
   处理专有实例路由。标准 `/v1/videos` 又委托给它。因此专有 `model:instance_id` 出现在
   列表中，也不能证明统一视频入口能够调用它。
3. 实例代理透传容器接口，不会自动统一原生参数。247 实例的历史验证中，标准创建请求失败，
   原生 JSON 请求成功；它的 `/videos` 路径和 OpenAPI 外观不能证明标准创建请求兼容。
   简化版本移除原生特例后，新生成实际报错缺少 `task`；旧任务恢复成功不能证明新生成兼容。
   本次增加通用的、明确配置的服务端请求映射作为本地兼容桥接：按准确连接 URL、模型 ID 和
   当前部署元数据绑定，不按模型名称推断，不改写地址；提交前读取实时模型信息校验部署身份。
   实例 247 的映射只保存在本机连接配置中，后续模型不会自动套用。详见
   [请求映射](VIDEO_REQUEST_MAPPING.md) 和 [验证记录](../tests/CONFIGURATION_RESULTS.md)。
4. 建议平台输出一致的能力契约：真实模态、必需参考输入、支持的时长与尺寸、音轨选项、
   可配置参数与兼容状态。未知字段不推断；模型原生参数适配及异步实例任务归属由平台负责。
   定价档位表示已配置价格，仍需模型服务验证实际尺寸/生成模式支持。

本次没有修改或部署 EcoLink 服务；以上服务端缺口不应被描述为插件配置错误。
